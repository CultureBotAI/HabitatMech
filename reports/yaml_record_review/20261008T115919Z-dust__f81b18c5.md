## Findings

1. **Major: house is a contextual container, not a broader dust habitat.**
   `parent_habitats` currently asserts ENVO:01000417. Primary class definitions
   and the executed parent route establish a material-versus-building error.
   Maintained owner: `curation/gold_parent_exclusions.tsv`, keyed to this mint,
   exact full path and expected resolved house parent. The independently
   supported ENVO:00002008 parent must survive.
2. **Major: mapping/status endpoint contract mismatch.**
   `SourceAttestation.mapping_predicate` says source concept to record identifier,
   omitting the predicate when the record is the source concept; GroundingStatusEnum
   likewise describes identifier versus source. This mint represents that exact
   source path, but its locally generated NARROW/narrowMatch describes the
   relationship to an ontology candidate which is instead stored as a parent.
   This is another witness for existing open [issue #1398](https://github.com/CultureBotAI/HabitatMech/issues/1398),
   read during the review. Owners: schema descriptions, `src/habitatmech/seed.py`
   resolution/attestation logic, and actual mapping consumers. It is not a claim
   that SKOS forbids hierarchical self-links: the [SKOS reference, section 10.6.4](https://www.w3.org/TR/skos-reference/#mapping)
   explicitly does not impose irreflexivity. Swapping broadMatch/narrowMatch
   alone cannot repair an implicit target mismatch.

No blockers or separate minor findings.
